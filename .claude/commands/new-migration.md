# /new-migration

Argument: `$1` is the migration message in imperative mood (e.g. `"add tribute_entry table"`, `"add partial unique index on current legal versions"`).

## Steps

1. Read the model files that changed (`git diff backend/models/`)
2. Read `Docs/global/diagrams.html` ERD section for the intended schema
3. Delegate to the `migration-writer` agent with `$1` as the message
4. Agent will:
   - Run `uv run alembic revision --autogenerate -m "$1"`
   - Hand-review and fix the autogenerated file
   - Add partial unique indexes via raw SQL if needed
   - Add explicit `ondelete=` on FKs
   - Run upgrade → downgrade → upgrade round-trip locally
5. Report back with:
   - Migration filename
   - Destructive operations (if any) with justification
   - Any hand-corrections made to the autogenerated file

## Never

- Never commit a migration without a round-trip test
- Never drop columns without a two-phase plan
- Never skip `ondelete=` on a FK

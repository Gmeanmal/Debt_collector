- **MINIO-JANITOR-1 orphan payment-proof cleanup cron** (ref `planning/todo.md` W4 DECLARE-1 known follow-up, `feat(payments)`):
  - **Why:** the declare-as-sub flow uploads the proof to MinIO/S3 *before* inserting the `payment_declaration` row.   - **`services/cron/proof_janitor.py`** — `run_proof_janitor(session, *, dry_run, now, settings) -> JanitorSummary`. Hard cap at `settings.proof_janitor_batch_cap` deletes per run (default 1000) so a broken state can't balloon into a giant S3 bill in one tick. Returns a structured summary (scanned / referenced / orphan_candidates / within_grace / deleted / dry_run / batch_capped) — same summary used by dry-run and real runs.
  - **`services/storage/object_store.list_objects(bucket, prefix)`** — async generator over `(key, last_modified_utc)`, paginates through `list_objects_v2` transparently. `_S3Client` Protocol extended.
  - **`PaymentDeclarationDao.all_proof_keys()`** — returns the set of every non-null `proof_key` currently in the table. Single query.
  - **Scheduler wiring** — `workers/daily_cron.py` fires `_proof_janitor_job()` at **03:00 Europe/London** daily, after the overnight quiet period but before the 08:00 main cron. Honours the existing `CRON_ENABLED` flag.
  - **Config** — `proof_janitor_grace_hours: int = 24`, `proof_janitor_batch_cap: int = 1000` in `core/config.Settings`. No `.env.example` change required (defaults work for dev).
  - **Controller cleanup** — removed the two `TODO(DECLARE-follow-up)` markers in `declare_as_sub`; replaced with a one-line explainer pointing at the janitor.
  - **Smoke test:** seeded two synthetic orphans under `janitor-test/*.jpg`, ran dry-run with grace=now+1s → flagged both, ran real-run with simulated `now = real_now + 25h` → deleted both + one pre-existing orphan, bucket empty after. - **WEBSOCKET-1 realtime hub — envelope, heartbeat, realtime invalidations, porch_gate fix** (ref `planning/todo.md` W11, single `feat(notif)` commit `f0cb2ba`):
  - **Envelope protocol.** Every WS frame is now `{ "type": "<kind>", "data": {...}, "ts": <epoch_ms> }`. Existing `NotificationOut` payloads ship under `type: "notification"` (no consumer change beyond the hook routing). Three new event kinds wired into the server: `payment_declared` (emitted from the payment declaration controller after a successful create; target = contract's goddess; `{ declaration_id, sub_username, amount, category }`), `validation_resolved` (emitted from the validate/reject controller path; target = declaration author; `{ declaration_id, outcome, reason? }`), `contract_state_change` (emitted from the debt contract state-machine whenever a contract transitions; target = both parties; `{ contract_slug, new_state }`).
  - **Heartbeat.** Server emits `{type: "ping", ts}` every 20 s per connection using `asyncio.TaskGroup` structured concurrency inside `routers/ws.py` (Python 3.11+ guarantee: child tasks are cancelled together with the parent on client disconnect). Client replies `{type: "pong"}`. Server closes with code **1001** after 30 s without pong. Client updates `lastSeen` on every frame and closes locally after 30 s of silence to force reconnect — covers the case where the TCP session is wedged upstream of a heartbeat response but not yet dead.
  - **`porch_gate` WS-handshake fix (critical bug — every WS connection was 500ing).** Root cause: `dependencies=[Depends(porch_gate)]` at app level in `server/main.py:94` meant FastAPI tried to inject the dep into every WS handshake. The dep's signature took `Request` (HTTP-only), and FastAPI couldn't build a `Request` from a WS scope → `TypeError: porch_gate() missing 1 required positional argument: 'request'` → HTTP 500 at handshake, before `accept()`. Fix: retype the dependency as `HTTPConnection` (the Starlette parent class resolved for both http and websocket scopes — verified against `fastapi/dependencies/utils.py:371/493/713`). Added `if conn.scope.get("type") != "http": return` at the top so WS scopes short-circuit — WS endpoints authenticate via `?token=` inside the handler and enforce access state themselves.
  - **Client envelope router** — `useNotificationsSocket.ts` rewritten (139 lines). On every message: parse → guard isEnvelope → if `type === "ping"` reply `pong` → if `type === "notification"` and `isNotificationOut(data)` store-add → else route into a new `useRealtimeInvalidations(qc)` helper. Reconnect/backoff/4401/dispose logic preserved byte-for-byte. `routeRef.current` pattern keeps the route function current across reconnects without re-subscribing the effect.
  - **`useRealtimeInvalidations` (73 lines)** — pure helper with narrow type guards (`isPaymentDeclared`, `isValidationResolved`, `isContractStateChange`) so malformed frames no-op instead of crashing. Invalidations are routed through the existing `queryKeys` registry (no ad-hoc keys): `payment_declared` → `queryKeys.goddess.pendingValidations()` + `queryKeys.goddess.dashboardSummary()`; `validation_resolved` → `queryKeys.sub.payments()` + `queryKeys.sub.dashboardSummary()` + `queryKeys.notifications.all()`; `contract_state_change` → `queryKeys.goddess.contracts()` + `queryKeys.sub.contracts()` + `queryKeys.contracts.bySlug(slug)`.
  - **Docs** — §9.2 Real-time WebSocket in `Docs/specs.md` rewritten to describe the envelope, the four kinds, the heartbeat, and the client invalidation hook. New §9.3 Web Push added (see PUSH-1). Email renumbered to §9.4.
  - **Gate** — server `ruff format` + `uv run mypy` clean on changed files; pre-existing 7 test failures predate this slice (verified by `git stash`). Client `pnpm tsc --noEmit` + `pnpm lint` clean on changed files. Verified end-to-end: WS returns 403 close-before-accept on a bad token (correct), connects cleanly on a valid token, ping frames arrive every 20 s, payment_declared invalidates the goddess pending-validation query in real time.

### Added
- **ENTRY-1 porch layout for pending-entry-tribute subs** (ref `planning/todo.md` W2, single `feat(auth)` commit):
  - **Backend porch gate.** New `server/dependencies/porch_gate.py::porch_gate` FastAPI dependency, wired globally via `app = FastAPI(..., dependencies=[Depends(porch_gate)])` in `server/main.py`. Blocks all requests from users whose `status == pending_entry_tribute` unless `(request.method, request.url.path)` is on `_PORCH_ALLOWLIST` — a `frozenset[tuple[str, str]]` containing `(GET, /auth/me)`, `(POST, /auth/login|logout|refresh|password-reset/{request,confirm})`, `(POST, /sub/payments)`, `(GET, /health)`. Method-scoped so `GET /sub/payments` (history) stays blocked while `POST /sub/payments` (entry-tribute declaration) is reachable. Returns `HTTP 403` with `{error, message, access_state}` body + response header `X-Access-State: pending_entry_tribute`. Unauthenticated / malformed-token / non-porch-status requests pass through untouched. Admin impersonation bypass: when the decoded JWT carries `imp`, the gate returns early so an admin impersonating a porch sub retains full-app access.
  - **CORS expose.** `CORSMiddleware` now lists `expose_headers=["X-Access-State"]` so the browser can actually read the gate header on cross-origin 403 responses.
  - **Entry-tribute amount on /auth/me.** `schemas.auth.UserOut` grows `entry_tribute_amount: Decimal | None`. `AuthController` takes an optional `InvitationDao` and exposes `get_entry_tribute_amount(user_id) -> Decimal | None` — fetches the invitation that was used by the current user and returns its `entry_tribute_amount`. `auth.router.me` calls the controller only when `ctx.user.status == pending_entry_tribute`; None otherwise. New `InvitationDao.get_by_used_by_user_id(user_id)` query. All DB access funnelled through the controller — no DAO import in the router.
  - **Frontend porch shell.** New `components/layout/PorchLayout.tsx` — full-screen single-card layout showing entry-tribute amount in `Intl.NumberFormat("en-GB", { style: "currency", currency: "GBP" })` with a primary CTA "Declare entry tribute" → `/sub/payments/new?kind=entry_tribute`. New `components/layout/PorchGuard.tsx` wraps `ProtectedRoute` children and redirects to `/porch` when `user.status === "pending_entry_tribute"` and the current path is not on the sub-porch allowlist (`/porch`, `/sub/payments/new`). New `routes/sub/PorchRoute.tsx` — auto-navigates to `/sub/dashboard` once the status flips to `active` (covers the post-payment flip without a hard reload).
  - **Payment form adapter.** `routes/sub/PaymentFormRoute.tsx` — `kind=entry_tribute` query param locks the form to `category=entry`, prefills `amount` from `user.entry_tribute_amount`, disables non-entry category radios, and redirects back to `/porch` on submit (instead of `/sub/payments`).
  - **Router wiring.** `router.tsx` adds `/porch` as a `noLayout` protected route; `/pending-entry-tribute` redirects to `/porch`. `routes/public/SignupRoute.tsx` now navigates to `/porch` post-signup. Orphan `routes/sub/PendingEntryTributeRoute.tsx` deleted.
  - **Types.** `client/src/types/api.generated.ts` regenerated via `make sync-types` so `UserOut.entry_tribute_amount` is first-class on the client.
